# Промпты для аудита и роста магазина

Готовые задания для Claude Code по методике Anthropic для Opus 5.5 (плейбук «Getting the most out of Opus 5.5»
и гайд «Как работать с Opus 5.5»). Скопируйте нужный промпт, заполните квадратные скобки и отправьте одним
сообщением.

- [audit.md](audit.md) — аудиты: обзор рисков и проверки по областям (безопасность, деньги, стоимость Firestore,
  скорость, UX, код, инструкции для Claude).
- [scaling.md](scaling.md) — рост: куда расти, больше товаров и посетителей, больше заказов, сотрудники, онлайн-оплата,
  поиск, большая функция, код и тесты под рост, резервные копии.
- [../templates/](../templates/) — шаблоны файлов, которые Claude заполняет: план аудита, спецификация функции,
  `TASKS.md`.
- Короткие брифы на каждый день и ревью ветки перед слиянием — [../briefs.md](../briefs.md).

## Как устроена работа

Круг, по которому уже прошли UI-аудит и этапы 1–8 (`docs/ui-audit-plan.md`):

1. **Аудит или план роста** — один PR с файлом плана в `docs/`, без правок кода. Вы читаете план, раздел
   «Ждёт владельца» и порядок этапов.
2. **Этапы** — по одному PR на этап, каждый от свежего `main`:

   ```
   Сделай этап [N] из `docs/[план].md` — «[название этапа]». Готово — это PR «Этап N из M: …» только с этим этапом,
   отметкой «сделано» в плане и таблицей «что найдено — что сделано» в описании PR. Что найдёшь по ходу и что не
   входит в этап — в «Найдено» и в план, а не в код: иначе PR станет трудно проверить.
   ```

3. **Повторная проверка** — тот же промпт аудита через время; сделанное в плане он не повторяет.

Что уже записано в `CLAUDE.md` и в промптах не повторяется: когда останавливаться и спрашивать, отчёт
«Ждёт меня / Изменено / Найдено», проверки перед PR, ветка от свежего `main`, запись в боевую базу только вами.

## Что есть в каждом промпте — правила плейбука

| Правило | Как выглядит в промпте |
|---|---|
| 7. Зачем | Первая строка: для кого и что это даст |
| 1. Вся задача и финишная черта | Что сделать целиком и «Готово — это …»: файл, что в нём, как проверить |
| 3. Причина вместо запрета | Каждое ограничение — с «потому что» |
| 4. Когда остановиться | «Останавливайся и спрашивай, только если …» — там, где CLAUDE.md не хватает |
| 5. Конкретная проверка | Доказательство к каждой находке (тест, замер, строка кода, скриншот) и «отметь, что не смог подтвердить, и где искал» вместо «перепроверь» |
| 2. Без «думай» | Таких строк нет: глубину задаёт effort |
| 6. Интервью | Если задача не ясна целиком — промпт 0 в `scaling.md` или `/prompt-brief` |

Большая работа раздаётся субагентам, по одной области на каждого. Прежде чем принять находку субагента, Claude
проверяет его доказательство, а в конце сводит всё в одну таблицу.

## Как запускать

- **Effort** (`/effort`): `medium` для всех промптов здесь. Выше — только если на своей задаче заметили, что стало
  лучше: на высоких уровнях Opus 5.5 думает заметно дольше.
- **Уходите, пока идёт прогон.** Claude ведёт `TASKS.md` (шаблон — `docs/templates/tasks.md`) и не останавливается
  без нужды. Вернувшись, первым читайте раздел «Ждёт меня».
- **Вспомнили условие посреди работы** — допишите сообщение и нажмите Enter, перезапускать не нужно.
- **Скриншоты, графики, выгрузки** прикладывайте файлом, а не пересказом.
- **Цифры в скобках** (`[1 000 товаров]`) замените своими: от них зависят прогнозы и выбор решения.
