# Поиск и ссылки на товары: план работ

Разбор проведён 03.10.2026 на `main` fdacefb (этап 2 аудита UX уже слит): код навигации (`src/utils/navigation.ts`,
`App.tsx`), `index.html`, `firebase.json`, `deploy.yml`, правила чтения каталога; каталог боевой базы прочитан как
анонимный посетитель через REST (7 товаров, только чтение). Страницы этапа 1 проверены на эмуляторе Hosting (адреса,
заголовки кэша) и в браузере на эмуляторах Firestore на 390 и 1280 px.
Не проверялось: заголовки живого сайта (песочница не пускает на `web.app`), превью в самих Telegram и WhatsApp — его
видно только на preview-ссылке PR (см. «Как проверить» в PR этапа 1).

## Ждёт владельца

- Этапы 1–3 решений не ждут: адрес сайта — `ai-studio-applet-webapp-e9574.web.app`, денег они не требуют.
- Этап 4 (по желанию, когда решите): свой домен (≈ 200–900 ₽ в год за `.ru`, подключается в Firebase Console) и
  подтверждение сайта в Яндекс Вебмастере и Google Search Console — это вход в ваши аккаунты, без вас не сделать.
  Свой домен лучше подключить до того, как ссылки разойдутся: поисковики и мессенджеры запоминают адрес.

## Варианты

| Вариант | Что даёт | Цена в работе | Цена в деньгах | Решение |
|---|---|---|---|---|
| А. Страницы товаров при сборке на Hosting | Превью с фото и ценой в мессенджерах, страницы в поиске, sitemap | 3 этапа | 0 ₽ (Spark: 10 ГБ хранения, 360 МБ трафика в день; ≈ 10 чтений базы на сборку) | **Выбран** |
| Б. Cloud Function на `/product/**` рисует страницу из базы | То же, но всегда свежо, без пересборки | 1 этап | Нужен тариф Blaze (карта); при нынешнем трафике ≈ 0 ₽ | Не сейчас: Blaze не покупаем (решение владельца). Можно перейти позже, адреса те же |
| В. Cloudflare Worker перед своим доменом | Свежо, без Blaze | 2 этапа и настройка вне репозитория | Домен + бесплатный тариф Cloudflare | Только со своим доменом; лишнее звено, которое придётся сопровождать |
| Г. Внешний пререндер (prerender.io и подобные) | Готовые снимки страниц для ботов | 1 этап | Платный тариф сервиса, данные магазина у третьей стороны | Нет |

Как работает вариант А:
- `scripts/share-pages.ts` после `vite build` читает каталог через REST как любой посетитель (товары, `settings/storefront`
  и `product_photos` читаются всеми по `firestore.rules`) и пишет `dist/product/{id}.html` — тот же `index.html`, но
  с заголовком, описанием, `og:*`, ценой и разметкой Product (JSON-LD) товара. `cleanUrls` в `firebase.json` отдаёт его
  по адресу `/product/{id}`. Фото, которое хранится в базе как `data:`, сборка кладёт файлом в `dist/share/`.
- Товар, у которого страницы ещё нет (добавлен после сборки), открывается по тому же адресу: rewrite `**` отдаёт
  `index.html`, только превью у ссылки общее. Снятые с витрины товары страниц и строк в sitemap не получают.
- Отзывы и рейтинг в разметку не идут: в товаре лежат поля шаблона `rating`/`reviewsCount`, а настоящий рейтинг —
  только по коллекции `reviews` (`getProductRating`). Добавить честный рейтинг можно позже, если отзывов станет много.

## Этап 2. Адреса без `#` — не начат

- `navigation.ts`: `routePath`/`parseRoute` по `location.pathname`; `productHref` — `/product/{id}`. Старый адрес
  `#/…` читается и заменяется новым через `replaceState` (без новой записи истории): разосланные ссылки работают.
- `App.tsx`: синхронизация экрана и `popstate` сравнивают путь, а не `hash`; `windowHistory.ts` пишет записи без
  адреса и не меняется. Ссылки-карточки (`productHref`) уже перехватывают нажатие — проверить, что переход не
  перезагружает страницу (иначе — заново весь каталог).
- `index.html`: убрать перевод `/product/{id}` → `#/product/{id}`; `canonical` экрана — его путь.
- Проверить: «Назад» по всем сценариям этапа 2 аудита UX (`docs/ux-audit-2026-10-03/scenarios/back-button.mjs`),
  вход через Google (возврат на тот же экран), уведомление о заказе (`notification-sw.js` открывает адрес), оферта и
  политика (`LegalDocumentScreen` берёт адрес из `location`), preview-канал.

## Этап 3. Свежие превью по расписанию — не начат

- Workflow по расписанию (раз в час, репозиторий публичный — минуты Actions бесплатны) и кнопкой «Run workflow»:
  читает каталог, сравнивает отпечаток полей превью (название, цена, описание, фото, «в продаже») с `share-manifest.json`
  на сайте и только при разнице собирает `main` и публикует **только Hosting**.
- Публикует только коммит `main`, у которого прошёл обычный деплой (`deploy.yml` зелёный на этом SHA): непроверенный
  код расписание не выпустит. Правила Firestore и функции не трогает.
- В форме товара — подсказка «Превью ссылки обновится в течение часа».

## Этап 4. Свой домен и поисковики — ждёт владельца

- Домен подключает владелец в Firebase Console (Hosting → «Добавить домен»), затем — переменная GitHub `SITE_URL`
  (её уже читает сборка) и домен в «Разрешённых доменах» входа (README → «Деплой»).
- Подтверждение в Яндекс Вебмастере и Search Console — мета-тег или файл в `public/`, его пришлёт владелец; там же
  отправить `sitemap.xml`.
