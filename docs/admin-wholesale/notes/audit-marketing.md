## Расхождения

Сравнение с остальной админкой (правила из `CLAUDE.md`, раздел «Админка», и с `AdminProductsTab`, `AdminListEditor`, `AdminPaymentTemplatesCard`).

1. Сохранение баннера не ждёт базу. `onUpdateBanners` объявлен как `=> void` (Banners:37), `handleUpdateBannersList` не возвращает результат (`ProfileAdminPanel.tsx:197-200`), хотя `handleUpdateBannerSlides` уже возвращает `persist(...)` (`app/useAdminActions.ts:145-155`). Тосты «Баннер успешно обновлен», «добавлен», «перенесен», «скрыт», «удален» (Banners:79, 311, 332, 345, 354) и сброс формы (335) идут до ответа базы. У промокодов всё сделано правильно: `Promise<boolean>`, ошибка остаётся в форме (Promo:42, 325-338). Правило `CLAUDE.md`: «Сохранено» — только после ответа базы.
2. Проверка формы. Промокод: `noValidate`, список ошибок над кнопками, `role="alert"`, фокус (Promo:785, 1295-1306). Баннер: нет `noValidate` (Banners:419-422), поле «Главный заголовок» `required` вызывает системный пузырёк, а собственные ошибки — тосты `error` (Banners:272-281), которые не исчезают сами (`CLAUDE.md`: «без тостов»). Тост «Введите заголовок» при `required` почти недостижим.
3. Подписи полей. Промокод: `<label htmlFor>` + `id` (Promo:805 и далее). Баннер: `<label>` без `htmlFor`, поля без `id` (Banners:457-507, 549-551, 977-993). Правило: «видимая подпись `<label htmlFor>`».
4. Кнопка статуса. Промокод «Активен / Пауза» (Promo:1428), баннер «Активен / Скрыт» (Banners:1115); обе — обычные кнопки, не `NeumorphicSwitch`/`aria-pressed`, надпись показывает состояние, а не действие. Тосты по-разному: «активирован / приостановлен» (Promo:348) и «показывается / скрыт» (Banners:345).
5. Подтверждение удаления без превью. `ConfirmDialog` без `preview` (Promo:1536-1542, Banners:1220-1226), тогда как в `AdminPaymentTemplatesCard.tsx:230` и `AdminProductCardStructure.tsx:677` превью удаляемого есть (правило «Удаление… через `ConfirmDialog` с `preview`»). У баннера было бы естественно показать миниатюру.
6. Окна. Окно увеличения фото баннера — `fixed inset-0` прямо в разметке вкладки (Banners:1171-1175), без `ModalPortal`; `CLAUDE.md` требует портал, иначе окно внутри `.neu-modal` обрезается. Не проверено в браузере (см. «Не подтверждено»).
7. Форма не закреплена. «Отмена / Создать» лежат в конце длинной формы (Promo:1309-1325, Banners:1005-1020), а у формы товара закреплены внизу окна (`CLAUDE.md`, раздел «Админка»). Формы раскрываются вверху списка, прокрутки к форме после «Редактировать» нет (`scrollIntoView` в обоих файлах не найден).
8. Длинные списки. «Заказы» и «Клиенты» — по 20 с «Показать ещё» (`usePagedList`); у промокодов списка-порций, поиска и фильтра по статусу нет (Promo:1364-1532). Пачка из 100 кодов добавляет 100 карточек в «Все промокоды» (Promo:431, 457-460).
9. Цвета и размеры. Карточки в одном стиле, но кнопки «выше/ниже» у баннера 20×20 px (Banners:1059, 1073), меньше минимума 24 px; чипы пресетов расписания ≈ 22 px высотой (Banners:948 и далее: `py-0.5`, 11 px).
10. Тексты бренда и тестовый контент. Кнопки «Готовые стильные фотографии» подставляют фото Unsplash (Banners:125-151, 895-899): покупатель увидит сток, хотя `CLAUDE.md` для товаров прямо запрещает сток («без фото — нейтральная заглушка, не сток»).
11. Разные «действия по нажатию на карточку»: у промокода меню «Ещё» нет вовсе, 3 кнопки на виду (Promo:1418-1448); для остальных списков админки правило — 2–3 частых действия на виду, редкие — в `AdminActionMenu`. Здесь редких действий нет, так что расхождения по сути нет, но «Копировать код» отсутствует (его нет и у карточки в списке, есть только у пачки).
12. Начальный и сброшенный бейдж различаются. Начальное состояние `badgeText = 'Новый купон'` (Promo:78), а `resetForm` ставит `''` (Promo:165): первый открытый «Новый промокод» получает бейдж «Новый купон», а после любого сохранения/отмены — пустой. Аналогично у баннера: начальный `badge = 'АКЦИЯ'` (Banners:99), после `resetForm` — `''` (164).

## Промокоды и опт

В коде оптовых цен и упаковок-ростовок нет (поиск `wholesale|ростовк|оптов` по `src/` нашёл только размерные сетки `utils/russianSizing.ts`, `components/SizeCalculatorModal.tsx`, `views/profile/MeasurementsModal.tsx`; поиск по `docs/` ничего не дал). Ниже — предложение, не описание существующего.

Как считается сейчас: скидка берётся от «подходящей» суммы (`calcEligibleSubtotal`), минимальный чек — от всей корзины (`shared/orderPricing.ts:78-92`, 161-182). Все суммы идут только через `src/shared/orderPricing.ts` (и на сервере в `placeOrder`), поэтому любое новое поле — изменение расчёта в обоих местах.

Предлагаемые поля `PromoCode` (по умолчанию значения, при которых старые коды работают как раньше — только розница):

| поле | значения | зачем |
|---|---|---|
| `channel` («где действует») | `retail` (по умолчанию) / `wholesale` / `both` | владелец не должен случайно дать -20 % поверх оптовой цены; в форме — переключатель «Розница / Опт / Везде» |
| `stacksWithWholesalePrice` | да / нет (по умолчанию нет) | можно ли скидку кода применять к уже оптовой цене строки; «нет» — скидка считается только с розничных строк |
| `minPacks` или `minWholesaleQty` | число | условие «от N упаковок-ростовок» вместо «от N ₽» (минимальный чек для опта обычно в упаковках) |
| `discountUnit` | `order` / `pack` | фиксированная скидка «500 ₽ на заказ» или «50 ₽ за ростовку» |
| `wholesaleCommissionPercent` | число, по умолчанию 0 или как розничная | партнёрская комиссия считается с оптовой выручки отдельно (`utils/partnerCommission.ts`) |
| `floorPriceGuard` | предупреждение в форме | не давать скидку, после которой цена ниже себестоимости (`product_costs`, видна только админу) — предупреждение, не запрет |

Также нужно: подсказка в форме «Код не действует на оптовые заказы» (по умолчанию), и колонка «Розница / Опт» в карточке кода. Лимиты и вход через Google для опта — решение владельца (оптовик чаще входит в аккаунт, поэтому лимитированные коды к нему подходят лучше).
