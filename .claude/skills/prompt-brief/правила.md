## 1. Вся задача одним сообщением — с финишной чертой

**Суть.** Одно сообщение из трёх частей: что сделать целиком, что значит «готово», когда остановиться и спросить. Потом модель работает сама.

**Почему с Opus 5.5.** Плейбук ставит это первым пунктом: Opus 5.5 держит длинную работу из многих частей лучше, чем Opus 5, ранние тестировщики гоняли его на задачах по коду часами почти без присмотра. Но пятые модели чаще делают слишком много, чем слишком мало: гайд по Opus 5 предупреждает, что модель может расширить задачу и добавить шаги, которых не просили. Финишная черта говорит ей, где остановиться.

**Признаки нарушения:**
- задача разбита на «сначала… потом… затем…» или раздаётся по сообщениям;
- нет того, что должно лежать в конце: «сделай отчёт» без формы, объёма, файла;
- просят план или набросок там, где нужен готовый файл;
- непонятно, когда модели можно остановиться и спросить.

**Как исправить:**
- переписать шаги в одну задачу с результатом;
- финишная черта — проверяемая: «тесты проходят», «один HTML-файл: сводка на полстраницы, таблица по регионам, три графика»;
- просить готовый файл, а не план: по плейбуку таблицы и документы Opus 5.5 требуют меньше правки, чем у Opus 5;
- если вспомнил что-то посреди работы — дописать сообщение и нажать Enter, пока Claude работает. Прогоны стали длиннее, перезапуск стоит дороже.

**Пример из плейбука, на русском:**
```
Перенеси платёжные эндпоинты со старого клиента на новый.
Готово — это когда все эндпоинты работают через новый клиент, старый клиент удалён и тесты проходят.
Останавливайся и спрашивай, только если тест падает по причине, которую ты не можешь объяснить.
```

**Когда не нужно.** Задача на одно действие. Там хватает самой просьбы.

## 2. Без «думай внимательно» и «перепроверь»

**Суть.** Убрать строки, которые просят думать, рассуждать по шагам и перепроверять. Глубину мышления задаёт effort, а не фраза.

**Почему с Opus 5.5.** Второй пункт из «попробуй первым делом» плейбука: Opus 5.5 думает перед каждым ответом всегда и сам решает, сколько. В тесте Anthropic в чате без строки «думай внимательно» ответы начинались быстрее без заметной потери качества. Пятые модели проверяют свою работу сами; гайд по Opus 5 называет лишние просьбы проверить «сверхпроверкой»: они тратят токены и не улучшают результат. А просьбу переписать в ответ свои внутренние рассуждения Opus 5.5 может отклонить — это одна из категорий, по которым сообщение помечается.

**Признаки нарушения:**
- «думай внимательно», «думай шаг за шагом», «хорошенько подумай»;
- «перепроверь каждую цифру», «в конце проверь всё ещё раз», «запусти проверку отдельным агентом»;
- «распиши в ответе все свои рассуждения».

**Как исправить:**
- строки удалить;
- нужен быстрый ответ на простой вопрос — написать «Ответь сразу»;
- нужно понять, почему модель так решила, — «Объясни в трёх предложениях, почему выбрал такой подход»;
- такая просьба может заблокировать сообщение целиком, даже когда её просто цитируют — например, приносят промпт на проверку. Проверено 23.09.2026: проверка промпта с этой строкой дважды упала с отметкой `reasoning_extraction`, и в пересказе тоже. Если сообщение с промптом помечено или сессия переключилась на другую модель, строку нужно убрать из текста и сказать словами, что она там была;
- нужна проверка — заменить общую просьбу конкретной (правило 5);
- effort в Claude Code: Opus 5.5 стартует с medium, и по тестам Anthropic medium у него не хуже high у Opus 5. xhigh и max — для задач, где человек сам замерил, что стало лучше.

## 3. Причина вместо запрета

**Суть.** Вместо «НИКОГДА», «ВСЕГДА» и капса — ситуация и причина. Модель с причиной сама видит случаи, о которых автор не подумал.

**Почему.** Для пятых моделей Anthropic убрала больше 80% системного промпта Claude Code без потерь на своих тестах по коду; принцип статьи о контекст-инжиниринге — «раньше давали Claude правила, теперь пусть решает сам». В своих логах Anthropic находила в одном запросе противоречащие друг другу указания вроде «оставляй документацию, где уместно» и «НЕ добавляй комментарии» — модели приходится тратить мышление, чтобы разобраться, какое из них главнее.

**Признаки нарушения:**
- капс, восклицательные знаки, «никогда», «ни в коем случае»;
- правило без причины: «не трогай папку X»;
- два правила, которые спорят друг с другом;
- общий запрет в дизайне: «без типичного AI-вида», «сделай красиво».

**Как исправить:**
- к каждому ограничению — одна причина: «Исходные выгрузки не трогай: это единственная копия, восстановить её негде»;
- вместо «делай просто, не переусложняй» — ситуация (пример Тарика Шихипара из команды Claude Code): «Эта функция — эксперимент. Есть реальный шанс, что через месяц мы её удалим. Не строй ничего, что будет жалко выбросить»;
- в CLAUDE.md и скиллах можно запустить `/doctor` — Anthropic встроила туда эти принципы, команда подсказывает, что упростить.

**Исключение — дизайн.** Здесь, наоборот, работает список запретов, но конкретный. Плейбук: общая просьба «без типичного вида» просто меняет один шаблон на другой. Пример оттуда:
```
Не используй кремовый или почти белый фон, курсив в заголовках, нумерацию разделов 01/02/03, моноширинные подписи и кнопки-таблетки.
```
Потом посмотреть, что модель выбрала взамен, и дописать это в список. Противоречия с правилом нет: плох общий запрет, конкретный работает.

## 4. Скажи, какие остановки нужны

**Суть.** Для долгих задач — правило в CLAUDE.md: когда продолжать, когда остановиться и спросить. Плюс список задач в файле.

**Почему с Opus 5.5.** Плейбук описывает поведение прямо: на длинной задаче Opus 5.5 иногда останавливается, чтобы отчитаться, вместо того чтобы продолжать. Три вида таких остановок: сводка, которая называет следующий шаг, но не делает его; предложение продолжить; список решений, которые на самом деле ничего не блокируют. Модель слушается инструкций, где эти остановки названы. Если прогон всё же встал на «Продолжить?», достаточно ответить «продолжай».

**Признаки, что правило нужно:**
- задача долгая, и человек уйдёт, пока она идёт;
- в CLAUDE.md нет ничего про то, когда останавливаться;
- жалобы вида «он написал, что сделает дальше, и встал».

**Как исправить** — блок для CLAUDE.md (правило из плейбука, подогнать под свою папку):
```
Если шаг не требует моего решения — продолжай. Пиши статус в том же сообщении, что и следующее действие.
Останавливайся и спрашивай, только если без меня дальше никак, или перед чем-то необратимым: удалением данных или изменениями за пределами этой папки.
```
- **Список задач в файле:** «Веди список задач в TASKS.md. Отмечай пункт, когда он готов, и дописывай новое, что найдёшь». Долгий прогон забивает контекст, и Claude Code сжимает старые сообщения; файл это переживает, и по нему видно, где прогон.
- **Большая работа — субагентам** (аудит, перенос, разбор сотни файлов): «Отдай каждый [сервис] своему субагенту. Когда субагент отчитается, проверь его доказательства, прежде чем принять. В конце — одна таблица».

**Когда наоборот.** Человек сидит рядом и работает с моделью в паре — ему остановки как раз нужны. Тогда в CLAUDE.md пишется обратное: план в одну строку до начала и короткий итог в конце. Подтверждения на опасные команды остаются включёнными в любом случае.

## 5. Формат отчёта и конкретная проверка

**Суть.** Один раз задать формат итогового отчёта. Проверку просить не общей фразой, а конкретной задачей.

**Почему с Opus 5.5.** У Opus 5 была проблема многословия и жаргона, и Anthropic советовала настраивать голос строкой вроде «Отвечай по делу, коротко и сжато». Opus 5.5, по плейбуку, отчитывается яснее: что сделал, что нашёл и что ему нужно от человека — простым языком. Поэтому настраивается уже не голос, а формат отчёта. Третий пункт «попробуй первым делом»: когда длинный прогон закончился, сначала читать, что модель ждёт от человека.

**Признаки нарушения:**
- в CLAUDE.md нет формата итогового отчёта, а после прогонов приходится искать, что от тебя нужно;
- «перепроверь всё» вместо конкретной проверки;
- исследование или анализ без просьбы отметить неподтверждённое.

**Как исправить:**
- строка в CLAUDE.md: «Заканчивай каждый прогон тремя заголовками: Ждёт меня, Изменено, Найдено»;
- для анализа и исследования: «Отметь всё, что не смог подтвердить, и напиши, где искал»;
- для кода — ревью до того, как смотрит человек: «Проверь изменения в этой ветке против main. Перечисли только проблемы, из-за которых ты бы не пропустил слияние: файл и строка, почему это ошибка и как показать, что она падает»;
- для длинного документа: «Проверь документ на противоречия: числа, даты, имена. Процитируй каждую проблему и скажи, где она».

## 6. Не знаешь задачу целиком — сначала интервью

**Суть.** Если условия задачи неясны, сначала попросить модель задать вопросы и собрать из ответов бриф.

**Почему.** Правило 1 требует знать задачу целиком, а половина условий обычно всплывает, когда видишь первый результат. С Opus 5.5, который работает дольше, это стоит уже не одной переделки, а длинного прогона. Тарик Шихипар из команды Claude Code начинает с короткого описания и просит Claude проинтервьюировать его до того, как писать итоговое ТЗ.

**Признаки, что правило нужно:**
- в запросе много «как-нибудь», «на твоё усмотрение», «ну ты понял»;
- непонятно, для кого результат и что в нём главное;
- человек сам говорит, что не уверен, чего хочет.

**Фразы:**
```
Задавай мне вопросы по одному обо всём, что в задаче неоднозначно. Начни с тех, где от моего ответа сильнее всего меняется результат. Когда вопросов не останется — собери из ответов бриф.
```
Если человек не знает даже, чего хочет, — шаг раньше:
```
Придумай несколько направлений и сделай по каждому макет в HTML, чтобы я посмотрел.
```

**Когда не нужно.** Задача ясная и короткая — интервью только отнимет время.

## 7. Скажи «зачем»

**Суть.** Одна строка о том, для кого результат и что он должен дать.

**Почему.** Гайд Anthropic по Fable 5: модель работает лучше, когда понимает намерение за просьбой — контекст помогает ей связать задачу с нужной информацией, а не угадывать. Чем дольше модель работает без человека, тем больше мелких решений принимает сама: какой график, что поставить первым, что выкинуть. «Зачем» — это то, по чему она их решает.

**Признаки нарушения:** есть «что сделать», но нет ни читателя, ни цели.

**Шаблон Anthropic:**
```
Я работаю над [большая задача] для [кого]. Им нужно [что даст результат]. С учётом этого: [просьба].
```
Пример: «Я готовлю квартальный разбор продаж для руководителя. Ему нужно за пять минут понять, где просели продажи. С учётом этого: собери отчёт по выгрузке».

## Ещё из плейбука

Не правила, но пригодятся при проверке:
- **Картинки.** Прикладывать сам график, скриншот, схему и задавать конкретный вопрос, а не перепечатывать цифры. Opus 5.5 даже на самом низком effort снимает значения с плотных графиков точнее, чем Opus 5 на самом высоком.
- **Проекты в чате Claude.** Если в длинном чате короткие вопросы отвечаются медленно, в инструкции проекта: «Если ты уже на что-то ответил, считай это решённым. Не возвращайся к прошлым ответам, если я не спрошу». Не ставить в проекты с длинным анализом, где поздний шаг может найти ошибку в раннем.
- **Смена модели.** Если сообщение помечено защитой, работа продолжается на более старой модели. В Claude Code вернуться — `/model`, поправить последнее сообщение — дважды Esc.

## Шаблоны

**Бриф — одно сообщение:**
```
Я работаю над [большая задача] для [кого]. Им нужно [что даст результат]. С учётом этого:

[Что сделать — целиком, одной-тремя фразами. Где исходные данные.]

Готово — это [конкретный результат: файл, формат, что в нём; как понять, что сделано].

[Ограничение] — потому что [причина].

Останавливайся и спрашивай, только если [когда без меня дальше никак].
```
Строки, которые задаче не нужны, убрать. Для визуальной задачи — добавить список того, чего не делать в дизайне. Для анализа — «Отметь всё, что не смог подтвердить, и напиши, где искал».

**Блок для CLAUDE.md — долгие задачи:**
```
## Как работать в долгих задачах

Если шаг не требует моего решения — продолжай. Пиши статус в том же сообщении, что и следующее действие.
Останавливайся и спрашивай, только если без меня дальше никак, или перед чем-то необратимым: удалением данных или изменениями за пределами этой папки.
Если задача больше нескольких шагов, веди список в TASKS.md: отмечай сделанное, дописывай найденное.
Заканчивай каждый прогон тремя заголовками: Ждёт меня, Изменено, Найдено.
```

**Блок для CLAUDE.md — работа в паре:**
```
Перед началом работы скажи одной строкой, что собираешься сделать. В конце — короткий итог.
```
