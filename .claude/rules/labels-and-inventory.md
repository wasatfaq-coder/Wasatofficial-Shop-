# Склад и этикетки

- Этикетки: «Склад и SKU» → выбор вариантов → `AdminLabelGenerator` (форматы — `settings/storefront.labelFormats`,
  10 шаблонов и PDF — `src/utils/labels.ts`, превью и PDF по одной разметке, данные только из каталога, без названия
  магазина). Раскладка — колонка блоков с автоподгонкой (`solve`): масштаб текста подбирается под формат, лишнее место
  идет штрихкоду (до читаемого максимума), затем распоркам — без штрихкода цена и название крупнее, пустот нет; на
  малом формате сначала убираются необязательные строки (превью пишет, что не поместилось). Цена и название — самые
  крупные, текст только черный (термопечать). Пока у магазина нет своего формата, образцы шаблонов и предпросмотр
  рисуются на первом из «Частых размеров» (58×40) с подписью «Образец», а PDF не скачивается (аудит UX 03.10, находка 18).
- Артикул = товар + цвет: код без размера — `articleCode`, у всех размеров цвета один штрихкод
  (`unifyArticleBarcodes`); шаблон без размера печатает одну этикетку на артикул, «Скидка» — только при старой цене.
  Штрихкоды — `src/shared/barcode.ts`: новые только `generateInternalEan13` (EAN-13 «2…», уникальный в каталоге).
- «Склад и SKU» → «Остатки» (вкладки «Остатки», «Инвентаризация», «Журнал» — короткие, чтобы помещались на 390 px): группировка «По категориям» (категория → модель → артикул-цвет → размеры),
  «По моделям» или «Списком» (`InventoryGroupedList`, выбор запоминается в `manstyle_inventory_grouping`). Модели
  свернуты, поиск или фильтр статуса раскрывает совпавшие; галочка группы выбирает все ее варианты для этикеток
  (`aria-checked="mixed"`). Поиск — по названию, артикулу, штрихкоду, цвету, размеру и категории; фильтр «Категория» —
  категории из «Категорий».
- «Журнал» (журнал движений) — подписка на `stock_movements` (`subscribeToStockMovements`), а не `localStorage`: последние 500
  или все записи за 30 / 90 дней / год (`since`, не больше `STOCK_MOVEMENTS_PERIOD_LIMIT` = 5000; находка 42 аудита 02.10).
  Новую запись делает `stockMovementId()` и `saveStockMovements`; журнал, оставшийся в браузере от прошлых версий
  (`manstyle_stock_movement_logs`), админка один раз переносит в базу.
- «Мало на складе» — один порог магазина `settings/storefront.lowStockThreshold` (выбор 2 / 3 / 5 в «Складе», пишется
  в базу; этап 9 `docs/admin-wholesale-plan.md`, находка 5): список товаров, форма товара и склад считают только
  `stockLevel(остаток, lowStockThresholdOf(settings))` из `src/utils/inventory.ts` («мало» — не больше порога). Своих порогов
  и `< 3` в коде не писать.
- «Оформить операцию» — один товар, количество у каждого цвета и размера (ключ — «цвет|размер», не позиция), одна
  операция `applyAdminStockChanges` с записью журнала на вариант; списание не ниже нуля, непрошедшие варианты остаются
  в окне. Окно открывается пустым.
- Этикетки: «Копий каждой этикетки» (1–200, `LABEL_COPIES_MAX`) — `downloadLabelsPdf(…, copies)` повторяет страницу
  каждой этикетки, картинка рисуется один раз.
